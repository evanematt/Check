# Архітектура

## Стан кампанії
* `logic/LewState` — єдине джерело істини на сервері (`PersistentState`, ключ `lewandivka`). Зберігає прапорці-віхи,
  здібності гравців, точки локацій, UUID босів і вашу версію даних `DATA_VERSION` (для майбутніх міграцій).
* `campaign/Stage` — 17 стабільних етапів. `campaign/Campaign.stage()` **виводить** етап із віх, тому він переживає
  рестарти й не розсинхронізується. `setStage` (адмін) виставляє віхи до потрібного етапу.
* `campaign/Campaign.partySize()` — розмір активної групи 1..3 (або `/lewandivka party N`). Механіки беруть розмір групи
  з нього, а не вимагають «рівно трьох»: `windowFor(1)=60 с, (2)=40 с, (3)=30 с` вікно синхронізації перемикачів.

## Мережа (Fabric networking, сервер авторитетний)
| Канал | Напрям | Зміст |
|---|---|---|
| `ability` | клієнт → сервер | `dash` / `glide`; сервер перевіряє наявність здібності, кулдаун, стан гравця |
| `notebook` | сервер → клієнт | дані блокнота |
| `hud` | сервер → клієнт | поточне завдання |
| `cat_command` / `open_cat_menu` | обидва | меню команд котів |

## Здібності
Зберігаються в `LewState` (не в предметах), видаються після босів і синхронізуються при вході (`syncOnJoin`).
Ривок і планер — серверна швидкість з кулдауном; пружні устілки гасять падіння.

## Боси
`entity/boss/ChromaBossEntity` — спільна основа (бос-бар, арена, захист, масштабування). Конкретні боси лише
додають умову вразливості та атаки. Скидання: `/lewandivka reset encounter <name>`.

## Виміри та структури
Вимір `lewandivka:chromandivka` (JSON у `data/`), будівлі локацій будуються кодом (`world/Sites`, `SiteBuilders`) за фіксованими
координатами при першому наближенні, тому квестові об'єкти не залежать від випадкового рельєфу.

## Збереження квестових предметів
`logic/QuestItems`: предмет «побачений» (`got_*`), ще не зданий — і його немає в жодного онлайн-гравця → відновлюється
(перевірка раз на 30 с, при вході й респавні). Таблетки Хроми повертаються, якщо синхронізація провалилась (`ChromaSync`).

## Пакування
Мод **не** вбудовує Fabric API чи чужі моди. `tools/build_pack.py` у CI збирає `.mrpack`, серверний і TLauncher-архіви
з Modrinth та генерує `THIRD_PARTY.md`.
