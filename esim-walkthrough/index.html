Product call: which data does the demo use?

Toggle “Demo data” above to see both in any variant. The label chips change; nothing else does.

(a) The user’s own number, read-only

  • Most relevant — they see their line and SIM
  • Needs airtight guarantees: every write path must be unreachable, not just the last button
  • Personal numbers appear in screenshots and screen-shares sent to support
  • Breaks for users with no eligible line (already eSIM, corporate, blocked)

(b) A placeholder number

  • Safe by construction — no real account data on screen
  • Identical for every user, so the script never dead-ends
  • Less concrete; “Demo number” tags carry the message
  • Needs a fixtures layer, which also makes the tour testable

Recommendation

Variant A’s strict tap-through, plus two things borrowed from C — the read-only/“nothing changed” cues and the three-facts end card — on placeholder data.

  • Build demo mode as a flag that swaps the data layer for fixtures, so there is no write call to guard. Revisit own-number only after that layer has shipped.
  • Keep B’s Next/Back as the fallback when a screen reader or switch control is active, since tapping a spotlit element is the hard part there.
  • Store the launch route when the tour starts; Exit returns to it. Here it is always Home.
